Ten Rooms and a Clipboard

The agent is a board game: ten squares, arrows between them, and one shared clipboard that every square writes on.

It's a board game, not a brain

Think of Snakes and Ladders. There are fixed squares, arrows between them, and a rule at certain squares that decides where you go next. A bad roll sends you back down a snake. The Coding Engineer works the same way, and engineers call this shape a state machine.

It's built with LangGraph. Each square is a node, and each arrow is an edge. Click any square below.

The clipboard every room writes on

Nodes don't phone each other. Each one reads a shared state object, does its job, and returns only the fields it changed. LangGraph merges those changes in. The state's shape is declared with a TypedDict. Here's one small piece of it: a single lesson learned from a failure.

CODE · state.py 
class Lesson(TypedDict):
    attempt: int
    plan_id: str
    failure_signature: str | None
    category: str | None  # added Phase 2 -- diagnose's LLM classification
    insight: str

Define a form called "Lesson" with exactly these boxes:

Which attempt number failed (a whole number).

Which plan was being followed, e.g. "plan-2".

A fingerprint of the failure, or nothing if there isn't one.

What kind of failure the AI thinks it was: syntax, logic, flaky…

One sentence of advice for the next attempt. This is the part future attempts actually read.

The arrows: who decides where to go next?

Some arrows are fixed ("after plan_tot, always code"). Others are conditional: a tiny router function reads the clipboard and names the next square. Routers are plain code with no AI in them, so the path is predictable.

CODE · engine.py 
    graph.add_edge("plan_tot", "code")
    graph.add_edge("code", "self_check")
    graph.add_conditional_edges(
        "self_check",
        _route_after_self_check,
        {"bdd_gate": "bdd_gate", "review": "review", "diagnose": "diagnose"},
    )

CODE · nodes.py 
def _route_after_self_check(state: CodingLoopState) -> str:
    if not state["test_report"]["passed"]:
        return "diagnose"
    # In pytest mode self_check IS the test gate, so a green one goes straight
    # to the reviewer; there are no scenarios for bdd_gate to run.
    return "review" if state.get("test_style") == "pytest" else "bdd_gate"
PLAIN ENGLISH

A router: look at the clipboard and return the name of the next square.

If the quick checks did not pass…

…go to the doctor (diagnose). That's the snake.

Otherwise, it passed. Which test style is this run using?

(The comment explains the edge case.)

Plain-pytest mode skips straight to review. BDD mode runs the frozen scenarios next.

💡
Keep decisions and work apart

Nodes do work and routers decide, and they're never mixed. When an agent misbehaves you can read the routers to see exactly why it went where it went. A good instruction for an AI tool: "keep routing logic in pure functions, separate from the nodes."

Where each kind of logic lives

The package is split so each file has one job. Knowing this lets you tell an AI "put that in gates.py, not nodes.py".
